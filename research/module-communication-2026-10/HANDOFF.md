## Что добавлено в план

- §1.4 сохраняет видение владельца: изолированные модули, один writer, явные контракты, надёжность для
  ИИ-авторов, механизм отдельно от продуктовой политики и отсутствие лишних общих систем.
- §2.3 фиксирует **TypeScript 7.0.2+ only** как уже данное разрешение владельца. Указаны реальные legacy pins,
  общий compiler helper, активные Core packed/parser gates и их владельцы, которые ещё требуют одного
  compiler checkpoint **до parser-dependent команд Phase 1a**. Governance/admission и ownership тоже
  используют legacy parser. Root экспорт TS 7 содержит version metadata; старый JS compiler API нужно
  действительно перенести на явные TS7 API/CLI с сохранением существующих проверяемых правил.
  Имена `m1-*` не превращают текущую проверку пакета в исторический replay.
  Новый запуск компилятора ниже 7.0.2 в этом delivery не разрешён; старые байты и результаты сохраняются.
- §7 исправляет план для callback-return isolation, detached ALS origin, проверки прототипов массивов,
  позднего watch/load и актуальности после startup await loader. Для watch заданы 65 revision-slots на ключ:
  старый снимок сохраняет причинность пропущенных commits, свежий исключает их. Первый load использует
  keys-only и причинность live-контекста регистрации. После `onLoading` повторно проверяется закрытие lane.
  Вся обработка возвращённых значений сохраняет guard-report deduplication по идентичности ошибки.
  Getter/thenable запускается под тем же origin/depth/live token, чтобы сама обработка результата не теряла guard.
  FIFO и исправления #183 сохранены.
- §7.6 и §8.1 задают применение API: состояние/команда/событие, атомарный агрегат, типы будущих снимков,
  структурную инвариантность writer, владение async-completion и точный смысл диагностик.
- §9.7 задаёт воспроизводимые R18–R23 и контроли, распределённые по уже запланированным тестам.
- §14 оставляет один bounded TEST с независимым небольшим consumer, контролируемым I/O, двумя экземплярами,
  close и ошибками. Существующий CMS oracle отдельно фиксирует providers/inputs/roots через `checkWiring`;
  один smoke отвечает за свойство construction/cleanup. Это не новая кампания больших графов и не
  квалификация сотен production-модулей.
- §19 записывает хорошие практики и ограничения Jotai, MobX, XState Store, Solid, Svelte, Valtio, Nano Stores
  со ссылками на первичные источники и отдельными триггерами для отложенных идей.

## Проверка текущей редакции

**Завершены три круга по три независимых критика Astra xhigh — девять фактических полных отчётов.** Каждый читал
всё видение, план и исследовательский контекст; следующие круги также читали все предыдущие отчёты и dispositions.
Все существенные замечания внесены после своего круга. Точные входные SHA, имена критиков, результаты и решения
записаны в `plan-review.md`. После третьего круга root внёс две узкие правки: контекст обработки thenable и
существующий CMS binding oracle. Это исправления плана; проверки будущего пакета остаются невыполненными.

Самостоятельная проверка root включает объединённый кандидат read/future-snapshot + writer marker на TS 7.0.2:
NodeNext и Bundler. Динамические ключи не обещают лишних полей; union снимков сохраняет обычное сужение.
Два ранее положительных unsafe watch-only присваивания в p8 теперь отвергаются; T25 и §8.1 явно отражают
коррекцию исторического residual из ADR, исходный архив не изменён. Проход этого кандидата не
означает, что готова production-декларация или выполнены packed/Assembly/runtime gates.
Во втором круге отдельный критик также проверил p5/p10 на реальных workspace-декларациях Assembly/Core/resources
и прежние variance controls в обоих resolver modes. Это feasibility кандидата; итоговый пакет ещё нужно собрать.

Для документации использовать `docs-authoring`, `docs:info`, `docs:find`, context/check и
`docs:protocol:check`; changed/fast/full routes применять по фактическому скоупу и инструкции владельца об
отсутствии лишних проверок. Не запускать новый observation случай через helper с legacy 5.8.3.
Активный full gate с legacy compiler ещё требует миграции: не запускать его ниже разрешённого минимума,
не ослаблять и не выдавать исторический результат за новое TS 7 evidence.
