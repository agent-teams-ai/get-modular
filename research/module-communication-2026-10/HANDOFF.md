## Что готово

- Один writer, реальные read-only facets, scoped `watch`, последовательный `load`,
  catch-up через `await`, физический drain, отмена устаревшей работы и защита от echo/cascade.
- Два публичных entrypoint, точные будущие снимки и ключи, инвариантность writer,
  ошибки с атрибуцией, тестовые ожидания и счётчики.
- Полный `observation:check` на Node 26.11.1: build, 154 проверки, 18 мутаций,
  33 writer-задачи и packed consumer. Runtime/process: 149 проверок на каждой
  из Node 24.21.0 и 26.11.1. Пропусков observation нет.
- Внешний connected consumer: оба Node, оба resolver mode TS 7.0.2,
  33 writer-задачи на каждом Node, один smoke на 11 строках. Проверены точные
  байты пяти архивов и 176 установленных файлов, 78 исходных writer inputs.
- CMS, guide, компилируемые примеры, настоящий lint-контроль `/testing`,
  admission, шесть CI lanes и согласованные Changesets с миграциями.
- Собственные compiler readers и кодмоды перенесены на нативный TS 7.0.2.
  Семантические проверки, исходные фикстуры и замороженные свидетельства сохранены.
- Семь отдельных нетипизирующих Foundation capabilities, полный typed lint,
  governance/profile, обязательные 11 quality identities и проверки документации проходят.

Отдельной системы событий `createEvent` / `emit` / `subscribe` в этой поставке
нет: она за пределами принятого 0.1.0. Команды модулей задаются явными портами;
`watch` наблюдает состояние с выбранной семантикой пропуска промежуточных значений.

## Реальные оставшиеся ограничения

1. **Foundation/API Extractor всё ещё зависит от TypeScript 5.9.3.**
   Владелец разрешил только 7.0.2+. Полные `check`, `check:fast`, `check:changed`,
   Foundation/API и SDK-growth aggregates нельзя считать выполненными.
   [Исследование зависимости](typescript-toolchain-blocker.md) задаёт владельца
   и конкретный upstream-путь. Никаких overrides, пропусков, новых исключений
   или обновления sealed API baseline ради зелёного CI.
2. **ADR-0034 / PR #154 ещё не на main.** Точные байты `945e9a1` включены
   в рабочую ветку; это не выполненное условие допуска main. План #185 тоже
   остаётся предшественником. Их merge требует своего процесса.
3. macOS/Windows matrix и время Windows lane ещё не наблюдались. Linux E2E
   не подменяет их результаты. Таймаут workflow не увеличен.
4. Другие pinning consumers, включая AgentRuntime, должны отдельно просмотреть
   новый CMS digest и обновить свой pin. Весь frozen SDK-growth CMS JSON сохранён.
5. Merge и npm publication не выполнены. Подготовленная версия не означает
   release eligibility; публикация остаётся шагом владельца.

Codex Review игнорируется по инструкции владельца. Все остальные failures и
невыполненные строки отражаются прямо. Если меняются байты архива, нужен новый
точный candidate и повтор затронутых E2E-проверок; старый результат не переносится.

## Машина и воспроизведение

Использованы Node 24.21.0 / 26.11.1, pnpm 11.20.0 и TS 7.0.2.
Точные команды и машинные данные сохранены в локальной и внешней evidence-записях.
Путь к pnpm CLI передавался packed-тестам через `npm_execpath`; иначе тест
правильно отказывается угадывать или скачивать CLI. Для дочернего `node --test`
снимается унаследованный `NODE_TEST_CONTEXT`, чтобы дочерний тест действительно
выполнился. Ограниченный sandbox давал EPERM нативным процессам; рабочие результаты
получены через разрешённый запуск подпроцессов, без изменения ожидаемых результатов.

Прошлые сведения о Git hooks относятся к чужому fixture-треку, а не к хукам
Get Modular. Старый planning-хендофф сохранён в истории #185.
