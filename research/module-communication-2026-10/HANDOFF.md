## Что проверено после дополнительного ревью

- Полный `observation:check` на Node 26.11.1: build, оба resolver режима TS7,
  **157 реальных тестов**, **18 атрибутированных мутаций**, все **33 writer-задачи**
  и установленный packed consumer. Пропусков observation нет.
- Независимый критик на каждой Node 24.21.0 и 26.11.1: 45 guard-тестов,
  31 load-тест, оба no-ALS режима, три GC режима с нулём удержанных payloads.
  Исходный контрпример и неизменённые P17/R7/R17/R23 проходят.
- Новый точный внешний E2E: оба Node, оба resolver mode TS7.0.2, пять runtime
  предикатов и все 33 writer-задачи на каждом Node, один smoke на 11 строках.
  Проверены пять архивов, 176 установленных файлов, 78 writer inputs и 25 хешей
  исполненных исходников. Код consumer и семантические оракулы не менялись.
- Guard/CI/profile: автор прошёл 70 тестов на каждом Node; независимый критик
  повторил 21 инертный guard-контроль на каждом Node и проверил все границы.
- Реальные root `check:changed`, `check`, `quality:critical:test` и
  `sdk-growth:registry` теперь возвращают 1 с `TYPESCRIPT_COMPILER_FLOOR_BLOCKED`
  до входа в Foundation. Это блокировка, а не успешный гейт.

Первое ревью делали три независимых Astra xhigh критика. По последней просьбе
владельца дополнительное ревью сделали три независимых **GPT-6.1 xhigh** критика.
Далее использовать GPT-6.1 xhigh.

## Два новых исправления

1. Обычный Promise с геттером `constructor` проверялся повторно внешним `await`
   после выхода из loader-контекста. Запись на втором чтении обходила echo guard.
   Теперь сам `await`, обработка ошибки, закрытие live token и постановка
   публикации входят в один контекст. Геттер читается один раз; порядок публикации,
   физический drain и синхронный fallback сохранены.
2. Foundation загружает API Extractor и TS5.9.3 ещё до выбора команды. Guard
   дополнен на всех выявленных текущих CLI/Node runner/SDK import границах,
   включая прямые фикстуры и отдельно установленные registry subjects.
   Исходные команды, negative assertions и обязательные identities сохранены.

Важная поправка к прошлому отчёту: прежние успешные Foundation CLI проверки
инициализировали код TS5.9.3 и scanners. Их логи сохранены, но это не выполнение
исключительно на TS7. Само по себе это не доказывает разбор проекта или extraction
в нетипизирующих командах. Текущие защищённые команды заблокированы; пакетные,
нативные TS7 и изолированные внешние проверки имеют отдельную доказанную область.

## Реальные оставшиеся ограничения

1. **Foundation/API Extractor зависит от TS5.9.3.** Нужен поддержанный upstream
   переход и явный путь смены provenance экстрактора. Исторический registry subject
   тоже проверяется по собственным зависимостям. Нельзя делать overrides,
   пропуски, исключения или обновлять sealed API baseline ради зелёного CI.
   [Исследование зависимости](typescript-toolchain-blocker.md).
2. **ADR-0034 / PR #154 и план #185 ещё открыты.** Это заново проверено через
   GitHub после входа; точные байты включены в рабочую ветку, но main admission
   и merge этим не выполнены.
3. macOS/Windows matrix и время Windows lane требуют фактического CI результата.
   Linux E2E не подменяет их. Таймаут workflow сохранён.
4. Другие consumers, включая AgentRuntime, должны отдельно принять новый CMS pin.
   Весь frozen SDK-growth CMS JSON сохранён.
5. Merge и npm publication не выполнены; публикация остаётся шагом владельца.

Codex Review игнорируется по инструкции владельца. Остальные failures не скрывать.
Отдельная система `createEvent` / `emit` / `subscribe` не входит в принятую 0.1.0:
команды модулей задаются явными портами, `watch` наблюдает состояние с коалесцированием.
